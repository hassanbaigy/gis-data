01
ROLE & CONTEXT

You are building a working prototype of a fire-department field app called Hydrant Finder. Real fire crews will not use this build — it is intended for an internal demo. The goal is for an on-duty firefighter, sitting in a truck, to:

  1. Open the app on a phone or truck-mounted tablet
  2. Mock-log-in with a badge number + PIN
  3. See a map of past incidents and a big + NEW INCIDENT button
  4. Tap it, type the incident address, pick a type / alarm level, hit FIND HYDRANTS
  5. See the 3 nearest in-service hydrants, ranked by routed driving distance, with the route from #1 drawn on the map

You are not building a multi-tenant production system. Skip OAuth, audit logs, accessibility audits, i18n. Do build a clean dark-mode UI with big tap targets and the visual style spelled out below.

02
STACK
  • Next.js (latest, App Router) with TypeScript — npx create-next-app@latest hydrant-finder --ts --tailwind --app --eslint --src-dir=false
  • Tailwind CSS for all styling. No CSS modules, no styled-components. Use tailwind.config.ts to register the colors + font families below.
  • Mapbox GL JS (mapbox-gl v3 + @types/mapbox-gl) — load token from NEXT_PUBLIC_MAPBOX_TOKEN in .env.local.
  • Prisma + SQLite for incidents. Schema below. Run prisma db push on bootstrap; ship a seed.ts with 6 example incidents around the hydrant dataset.
  • Supabase client is installed and wired (env vars stubbed) but disabled in this prototype. Leave a lib/supabase.ts file that exports the client so it's a one-line swap from SQLite later. Auth is mocked.
  • Mapbox Directions API for the routed driving distance. Use profile=driving. No fallback — if the call fails, surface the error in the UI.
  • No other UI libraries. No shadcn, no Radix, no Headless UI. Build the primitives yourself — the design demands custom typography & chrome that off-the-shelf kits will fight you on.
  • Fonts via next/font/google: Barlow Condensed (700/800) as --font-display, Inter (400/500/600/700/800) as --font-ui, JetBrains Mono (400/500/700) as --font-mono.

Type rules

  • font-display (Barlow Condensed 800) — section heads, numerics, large CTAs. letter-spacing: -0.02em.
  • font-ui (Inter) — body, labels, secondary text. Labels use uppercase tracking-[0.16em] text-[10px] font-extrabold.
  • font-mono (JetBrains Mono) — badge numbers, hydrant IDs, coordinates, timestamps. Always.
  • Never go below 14px on a phone screen. Hit targets are at least 56px.

Hydrant pin convention

  • Blue dot (#3b82f6) — in-service pressurized
  • Blue dot, ringed yellow — also in-service, just stylistic for #2/#3 nearest
  • Yellow halo + yellow dot — the #1 chosen hydrant (the one being routed to)
  • Grey dot with an X through it — out-of-service / dry without pressure (still shown, but flagged)

DATA MODELS

Hydrant dataset (read-only, shipped in /public/data/hydrants.geojson)

GeoJSON FeatureCollection of Point features. Each feature has these properties (matching the dataset already in hand):

{
  "type": "Feature",
  "geometry": { "type": "Point", "coordinates": [-74.0060, 40.7128] },
  "properties": {
    "id":         "H-1156",
    "address":    "420 Elm St",
    "city":       "New York",
    "state":      "NY",
    "zip":        "10013",
    "in_service": true,
    "category":   "pressurized"   // "pressurized" | "dry"
  }
}

If the user has not yet supplied a real dataset, generate a plausible 40-feature sample around (40.7128, -74.0060) with a mix of pressurized / dry and ~10% out-of-service. Do not hit any external hydrant API.

Prisma schema (prisma/schema.prisma)

datasource db { provider = "sqlite"; url = "file:./dev.db" }
generator client { provider = "prisma-client-js" }

model Incident {
  id          String   @id @default(cuid())
  createdAt   DateTime @default(now())
  address     String
  lat         Float
  lng         Float
  type        String   // STRUCTURE | VEHICLE | BRUSH | MEDICAL | HAZMAT | OTHER
  alarmLevel  Int      // 1-5
  notes       String?
  unitId      String   // e.g. "E-12"
  badge       String   // from mock auth cookie
  chosenHydrantId String? // snapshot at create time
}

Mock auth

Login form accepts any 4-digit badge + 4-digit PIN. On submit, set an hf_badge http-only cookie with the badge value. lib/auth.ts exposes requireBadge() that reads it in server components / route handlers and redirects to /login if missing.

06
API CONTRACTS

POST /api/incidents

Body: { address, lat, lng, type, alarmLevel, notes?, unitId }. Server calls findNearestHydrants(lat, lng), stores the chosen hydrant id, returns { id, chosenHydrantId, hydrants: [...top3 with distance + duration] }.

POST /api/hydrants/nearest

Body: { lat, lng, k?: number = 3 }. Algorithm:

  1. Filter the dataset to in_service === true.
  2. Sort by haversine distance to the candidate (cheap pre-filter).
  3. Take the closest 10.
  4. Call Mapbox Directions Matrix (/directions-matrix/v1/mapbox/driving) with the incident as the source and those 10 as destinations. Get routed driving distance + duration for each.
  5. Sort by duration. Return top k.
  6. Also return the next 2 candidates flagged as out-of-service (for the "flagged" UI) — do not route through the matrix; just attach haversine distance.

Response shape:

{
  "nearest": [
    { "hydrant": {...feature props + coords}, "distanceM": 55, "durationS": 42, "geometry": {/* GeoJSON LineString from Directions API */} },
    ...
  ],
  "flaggedOos": [ { "hydrant": {...}, "distanceM": 125 }, ... ]
}

Only fetch the full route geometry for the #1 result (one extra /directions/v5 call). The other two only need distance + duration.

GET /api/geocode?q=…

Proxy Mapbox Geocoding v6 (server-side, never expose token to client). Cap to 5 results. Return { results: [{ placeName, lat, lng }] }.

GET /api/incidents

Query: ?since=7d&type=&unitId=. Returns { incidents: [...] } ordered createdAt DESC.

The prototype is "done" when, on a fresh clone:

  • pnpm install && pnpm prisma db push && pnpm prisma db seed && pnpm dev just works.
  • I can log in with 0418 / 1234, see 6 seeded past incidents on a dark map.
  • I can tap + NEW INCIDENT, type "418 Elm", pick the geocoded result, hit FIND HYDRANTS, and within ~1.5s I see the top 3 hydrants ranked by routed driving duration with a yellow dashed route drawn from #1 to my incident.
